PRECISIÓN QUE CABE EN EL ROBOT

Una red pequeña. Una línea más clara.

Lee 7 sensores cercanos a la línea, pasa por 8 neuronas y afina una posición. El control PD sigue dirigiendo el robot.

Así se conectan las neuronas

7 → 8 ReLU → 1

Azul: peso positivo · naranja: negativo. Más grosor significa más influencia dentro de cada capa. ReLU deja pasar solo valores positivos.

Pasa el cursor, toca o enfoca una conexión o neurona para ver su valor.

RMS: error típico. Unidad: milésimas de sensor (1 000 = 9 mm).

¿Qué pasa si las llantas agarran menos?

La red ayuda con agarre normal; al perder agarre no mejora todos los casos. Cada fila prueba 792 carreras y cuenta las fallas mientras el robot conduce.

SIEMPRE A MANO · SIN INTERNET

Actualiza. Abre. Decide.

Desde una terminal en la carpeta del proyecto, ejecuta estos tres pasos. Solo necesitas CMake, un compilador y Python 3 para regenerar los datos.

1. Preparar el simulador

Compila las herramientas del proyecto.

cmake -S . -B build && cmake --build build -j

2. Correr los mismos intentos con y sin red

./build/simulacion/atlas_sim --firmware --out resultados_simulacion/firmware && ./build/simulacion/atlas_sim --firmware --sin-red --out resultados_simulacion/firmware_sin_red

3. Actualizar este panel

python3 dashboard/generar_datos.py

Abre dashboard/index.html con doble clic. Si ya lo tenías abierto, recarga la página. Para consultar los datos existentes no necesitas instalar nada ni iniciar un servidor.

La curva y la evaluación se leen de los archivos guardados en entrenamiento/resultados; estos tres pasos actualizan las carreras, no vuelven a entrenar la red.
